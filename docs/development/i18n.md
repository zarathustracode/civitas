# Translation

Civitas ships in English, Spanish (`es`) and Polish (`pl`). Every string a visitor reads comes from a message catalog; adding a language is a content task, not a code change.

## How it works

- Catalogs live in `frontend/src/lib/i18n/messages/<locale>/<namespace>.json`. A key `hero_title` in `landing.json` is addressed as `landing.hero_title`. Each area of the app has its own namespace; `common` holds words several areas share (proposal statuses, ballot choices), `errors` holds API error codes and error pages.
- The server picks each request's locale: the `civitas_locale` cookie (set by the language picker in the footer), then the browser's `Accept-Language`, then English. It sets `<html lang>` to match.
- The root layout receives that locale's catalog and provides a translator through Svelte context. Context, not a global store: the server renders many requests at once, and a shared store would leak one visitor's language into another's page.
- A key missing from a translation falls back to English. CI fails before that ships (see [Checks](#checks)).
- User content — proposal titles and bodies, comments, display names, topic names — is shown as written. So are the emails the API sends, which are English for now.

## Using it in code

```svelte
<script lang="ts">
  import { getI18n } from '$lib/i18n';
  import Rich from '$lib/components/Rich.svelte';
  const i18n = getI18n();
</script>

<h1>{i18n.t('delegations.title')}</h1>
<p>{i18n.t('delegations.count', { count: rows.length })}</p>
<p class="[&_strong]:font-semibold">
  <Rich parts={i18n.rich('proposal.standing_direct', { choice })} />
</p>
<p>
  <Rich parts={i18n.rich('proposal.deliberation.empty')} href="/proposals/{id}/deliberate" />
</p>
<time>{i18n.date(proposal.created_at, { dateStyle: 'medium' })}</time>
```

Server code uses `event.locals.i18n`, e.g. `error(404, locals.i18n.t('errors.page.topic_not_found'))`. Form actions return error codes, and the page shows `friendlyMessage(new ApiError(code, code, 0), i18n)`.

Rules:

- **Whole sentences, with placeholders.** Never build a sentence from pieces (`'Posted by ' + name`); word order differs between languages. Write `"Posted by {name}"`.
- **Plurals by count, never by ternary.** A plural message is an object keyed by [CLDR plural category](https://cldr.unicode.org/index/cldr-spec/plural-rules), chosen by the `count` parameter:
  ```json
  "comment_count": { "one": "{count} comment", "other": "{count} comments" }
  ```
  English needs `one` and `other`, Spanish `one` and `other` (its `many` starts at a million and falls back to `other`), Polish `one`, `few`, `many` and `other`:
  ```json
  "comment_count": { "one": "{count} komentarz", "few": "{count} komentarze", "many": "{count} komentarzy", "other": "{count} komentarza" }
  ```
- **Emphasis or a link inside a sentence** uses `<strong>`, `<em>` or `<link>` in the message and the `Rich` component, never `{@html}`: `"No comments yet. <link>Open the thread</link> to start the discussion."` The page supplies the link's `href`, so translators move the link text freely but never touch addresses. Parameters are inserted as text, so a display name cannot inject markup.
- **Numbers and dates** go through `i18n.number` and `i18n.date`, never `toLocaleString('en-US')` or the runtime default, which differs between server and browser.
- **Case is styling.** Labels shown in capitals are written in sentence case; CSS uppercases them.
- **Every visible string counts**, including `aria-label`, `title`, `placeholder`, `alt`, and `<title>`.

## Checks

`src/lib/i18n/catalog.test.ts` runs with the unit tests and fails when:

- a locale is missing a key English has, or has one English lacks;
- a translation drops or renames a `{placeholder}`, or changes the `<strong>`, `<em>` or `<link>` tags;
- a plural message lacks a form its language needs (for Polish, `few` and `many`);
- the source names a key (`t('...')` or `rich('...')` with a literal) that no catalog defines.

## Adding a language

1. Add its code to `LOCALES` and its own name to `LOCALE_NAMES` in `src/lib/i18n/index.ts`.
2. Copy `messages/en/` to `messages/<code>/` and translate every file. Supply every plural category the language uses.
3. Run `pnpm test -- --run`. The catalog test lists anything missing.
4. Check the self-hosted fonts cover the script: the `@fontsource` packages imported in `app.css` include Latin, Latin Extended and (for Spectral and IBM Plex Mono) Cyrillic subsets; Public Sans has no Cyrillic.

## Style

Plain, direct and short, as the English is. Address the reader informally (Spanish *tú*, Polish *ty*) and prefer wording that does not assume a gender. Use each language's punctuation (Spanish `¿…?`, Polish `„…”`).
